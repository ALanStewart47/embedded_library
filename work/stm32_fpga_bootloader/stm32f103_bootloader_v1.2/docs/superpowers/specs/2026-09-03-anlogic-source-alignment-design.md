# 安路 FPGA 升级源工程语义对齐

## 目标

令 `stm32f103_bootloader_v1` 在启用 `BL_ENABLE_ANLOGIC_FPGA` 时，安路 FPGA 升级的正常协议与写入流程对齐 `../Boot_STM32_anlu`。保留目标工程的 MCU/Gowin 后端和可配置串口架构。

## 范围

修改仅限 `Core/Src/bootloader.c` 的安路协议分支和静态检查。不会修改用户本地未提交的 `Core/Inc/bootloader_config.h` 或 `MDK-ARM/stm32f103_bootloader_v1.uvprojx`。

## 行为设计

1. 保留源工程已使用的外部 Flash 参数：从 `0x0C0000` 起擦除 12 个 64 KiB 块，按 256 字节页写入，最后依次发送 `0xFFF2 = 0x0C`、`0xFFF1 = 0x00`，写 Bootloader 标志并复位。
2. 移除目标工程额外加入的连续包号、总包数为零和最大镜像长度拒绝；有效 CRC 的协商帧和数据帧按源工程接收并回复 `0x73`。
3. 协议 CRC 或协商参数无效时，仅发送源工程对应的错误回复；不得把 `up_cmd` 改为 `0xFF`，从而避免由本地额外状态机制造 `FB 02 FB`。
4. 保留两项刻意修正：空闲查询严格识别完整 `FB FF FB` 三字节帧，并在擦除、写入繁忙时由 UART IDLE 中断立即发送 `FB 01 FB`。这两项修正不改变源工程成功升级序列，且避免源工程的索引笔误和同步擦除阻塞问题。
5. 不改变当前 GPIO 引脚定义、Flash 指令、WIP 无限轮询、FPGA 控制时序或上电重载顺序；这些已与源工程的实际升级流程对应。

## 验证

增加静态回归检查，断言安路分支不再包含连续包号、镜像容量或 `up_cmd=0xFF` 的额外拒绝，且仍包含固定擦除区域、无限 WIP 等待、完整空闲查询判断和繁忙中断应答。执行现有静态检查和安路 Keil rebuild；硬件上用 2,449 包镜像复测擦除、写入和 FPGA 重载。
